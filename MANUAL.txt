AIRGAP UPDATE PLATFORM - BETA 0.1.0 - RUN MANUAL
================================================
Mutual-TLS update server + isolated agents (M0 milestone).
Last updated with the beta push.

WHAT THIS IS
------------
A central server (airgap-server) that is the ONLY machine online, plus
lightweight agents (airgap-agent) that run on isolated machines and only
talk to the server over mutual TLS. Agents enroll once with a token, get a
client certificate, register, and report their package inventory. The
server stores everything in JSON.

REPOSITORY LAYOUT
-----------------
  Cargo.toml            Cargo workspace (proto + server + agent crates)
  crates/proto          shared wire types (the API contract)
  crates/server         the server: CA, mTLS endpoint, JSON store, routes
  crates/agent          the agent: inventory, enrollment, registration, poll
  MANUAL.txt            this file

PREREQUISITES (on the build machine)
------------------------------------
  - Rust stable toolchain
  - musl target (for fully static binaries):
        rustup target add x86_64-unknown-linux-musl
  - An internal CA provisioned by the server on first boot.

BUILD
-----
  # debug
  cargo build

  # release (static, recommended for deployment):
  cargo build --release --target x86_64-unknown-linux-musl

  Binaries:
    target/x86_64-unknown-linux-musl/release/airgap-server
    target/x86_64-unknown-linux-musl/release/airgap-agent

RUN THE SERVER (on the machine that will be the update server)
--------------------------------------------------------------
  AIRGAP_STORE_DIR=/var/lib/airgap-server \
  AIRGAP_LISTEN=0.0.0.0:8443 \
  AIRGAP_HTTP_LISTEN=0.0.0.0:8080 \
  ./target/x86_64-unknown-linux-musl/release/airgap-server

  Environment variables:
    AIRGAP_STORE_DIR    state directory (agents.json, reports.json,
                        catalog.json, tokens.json, updates.json,
                        ca/, certs/)
                        DEFAULT: "data" (relative to CWD - always set this!)
    AIRGAP_LISTEN       mTLS API address        DEFAULT: 0.0.0.0:8443
    AIRGAP_HTTP_LISTEN  dashboard/HTTP address  DEFAULT: 0.0.0.0:8080
    AIRGAP_ENROLL_TOKEN enrollment token seed    DEFAULT: airgap-bootstrap
    AIRGAP_ADMIN_PASSWORD initial dashboard admin password (first boot only)
                                             DEFAULT: admin (change this!)

  On first boot the server generates its own CA (ca.pem + ca-key.pem),
  a server certificate, and the default enrollment token. Keep the state
  directory! If you restart without AIRGAP_STORE_DIR a fresh CA is created
  and every already-provisioned agent becomes invalid.

  API endpoints (all JSON, HTTPS on :8443):
    POST /enroll     token + hostname  -> agent_id, client cert, key, CA
    POST /register   agent_id + inventory
    POST /inventory  agent_id + inventory
    POST /updates    agent_id          -> pending updates list
    POST /report     agent_id + update_id + status
    GET  /health     -> JSON: status, agents, pending_approvals, last sync

  DASHBOARD (plain HTTP on :8080 - point a browser at the server's IP):
    GET  /                        web dashboard (v2, login required)
    POST /api/login               {"username":..,"password":..} -> session token
    POST /api/logout              ends the session
    GET  /api/me                  current operator + role
    GET  /api/devices             all devices + per-device update counts
    GET  /api/devices/<id>/packages   per-device installed vs latest
    POST /api/refresh             sync upstream apt/dnf metadata (catalog)
    GET  /api/refresh/status      live sync progress (phase/elapsed)
    POST /api/update              {"agent_id":..,"package":..} -> approval
    GET  /api/updates             pending update approvals
    GET  /api/audit               recent audit-log entries (operator actions)
    GET  /api/health              JSON health (devices, pending, last sync)
    GET  /api/operators           list operators (admin only)
    POST /api/operators           create operator (admin only)
    DELETE /api/operators/<name>  delete operator (admin only)

  Every /api/* call except /api/login requires the session token from login,
  sent as an "Authorization: Bearer <token>" header (the dashboard does this
  automatically). Roles: viewer (read-only), approver (can also approve
  updates and refresh the catalog), admin (also manages operators).
  Approvals and refresh require at least the approver role; operator
  management requires admin. Failed and successful logins are written to the
  audit log.

  First boot creates the operator "admin" with password from the
  AIRGAP_ADMIN_PASSWORD environment variable (default: "admin" - change it!).
  The operator list is stored (argon2-hashed) in <AIRGAP_STORE_DIR>/operators.json.

  On the server, an append-only audit log is kept in the state directory as
  <AIRGAP_STORE_DIR>/audit.log (one JSON line per operator action: logins,
  approvals, catalog refreshes, operator management, agent enrollments).
  It is NOT the same as reports.json (agent-reported install status).

  State files are written via temp-file + atomic rename so a crash mid-write
  cannot corrupt them.

  Open the dashboard at:  http://<server-ip>:8080
  It shows a card per device (hostname, OS, arch/kernel, IP, live relative
  last-seen, status, and how many updates are available). Clicking a card
  opens a drawer with that device's installed software vs the latest
  upstream version. "Refresh package catalog" shows live progress and fetches
  latest versions from Ubuntu (noble) and Rocky 8 metadata. "Approve &
  update" asks for confirmation and records an approval.

PROVISION AN AGENT (isolated machine)
-------------------------------------
  On each agent machine:
  1. Copy the server's CA certificate to the agent's state dir:
        scp /var/lib/airgap-server/ca/ca.pem root@<agent>:/var/lib/airgap-agent/ca.pem
  2. Copy the airgap-agent binary to /usr/local/bin/airgap-agent
  3. Run once with the enrollment token:
        AIRGAP_STATE_DIR=/var/lib/airgap-agent \
        AIRGAP_SERVER=https://<server-ip>:8443 \
        AIRGAP_ENROLL_TOKEN=airgap-bootstrap \
        /usr/local/bin/airgap-agent

  The agent enrolls, saves client.pem / client-key.pem (0600) and agent-id,
  registers, reports inventory, and polls for updates. Subsequent runs reuse
  the client certificate (no token needed).

  Environment variables (agent):
    AIRGAP_SERVER    server base URL   DEFAULT: https://172.16.5.20:8443
    AIRGAP_STATE_DIR state directory   DEFAULT: /var/lib/airgap-agent
    AIRGAP_ENROLL_TOKEN                only needed on first enroll

VERIFY / MANUAL TEST
--------------------
  1. Server health:
       curl -sk https://<server-ip>:8443/health      # -> "ok"
  2. Run an agent once per VM (enrolls + registers + reports):
       ssh root@<agent> 'AIRGAP_STATE_DIR=/var/lib/airgap-agent \
         AIRGAP_SERVER=https://<server-ip>:8443 /usr/local/bin/airgap-agent'
       It should log "registered as <agent-id>" and "server offered 0 update(s)".
  3. Check registered agents on the server:
       /var/lib/airgap-server/agents.json
  4. Open the dashboard:   http://<server-ip>:8080
       - sign in (first boot: admin / <AIRGAP_ADMIN_PASSWORD>, default "admin")
       - devices are shown as cards with IP, OS, arch, kernel, status and
         the number of available updates
       - click a card to open a drawer with installed vs latest versions
       - "Refresh package catalog" shows live progress and fetches latest
       - "Approve & update" asks for confirmation and records the approval
         (fleet-wide approvals live in the Approvals view)
  5. Audit log (who did what):
       tail /var/lib/airgap-server/audit.log
  6. Roles: sign in with a viewer account to verify read-only (no Approve
     buttons, POST /api/update returns 403).

NETWORKING NOTES
----------------
  - Agents must be able to reach the server's port 8443 (TCP).
  - For air-gapped use, put the server on the only internet-connected
    network and keep agents on an isolated subnet (no default route).
  - If firewalld is used:  firewall-cmd --add-port=8443/tcp
  - mTLS: agents must trust the server cert (ca.pem). The server only
    accepts clients with a certificate it issued (cert CN must match the
    agent_id on /register, /inventory, /report).

KNOWN LIMITATIONS (BETA)
------------------------
  - JSON file store (no database yet).
  - "Approve & update" records an approval; actual package install on the
    agent is the next milestone (agents currently only report versions).
  - Version comparison is best-effort (distro version strings are complex);
    a few packages may show a stale "latest".
  - Enrollment token is a single shared secret.
  - SELinux left Permissive in the lab; needs a hardening pass for prod.
