1. LATEST PLAN - THE AIR-GAP SYSTEM
============================================
Reference docs: PLAN.txt, RESUME.txt (the two-zone design), plan.md.

GOAL (unchanged)
  A WSUS-style secure update platform for a DevOps network so machines
  stay completely isolated from the internet while still receiving OS +
  software updates that are automatically downloaded, tested, approved,
  and distributed through a central server.

TOPOLOGY (two-zone, fully air-gapped)
  - ZONE A  = internet ingest + bundle builder. Only zone allowed online.
  - ZONE B  = air-gapped core server + clients. No internet, ever.
  - CONDUIT = the ONLY connection between the zones, and it is
    interchangeable: sneakernet/USB or a one-way data diode.
  - TRANSFER BUNDLE is the contract that makes the conduit swappable:
      catalog.json  (what is available, versions, metadata)
      artifacts/    (the actual packages / bundles)
      manifest.json (inventory of the bundle)
      manifest.sig  (signature; agents verify locally before anything runs)
  - Earlier single-box "server online, agents offline" (WSUS-relay) is the
    WIRED variant (section 2); the two-zone/diode design above is the true
    air-gap variant and remains the authoritative PLAN.txt architecture.

ZONE B CORE SERVER (WSUS analog)
  - Validator: verifies signatures + integrity of everything crossing the conduit.
  - Approval service + admin UI: human gate before anything is released.
  - Internal repos: aptly (apt) / zot (containers) / MinIO (bundles).
  - Rings: dev -> staging -> prod, per-package/per-bundle approval.
  - Immutable audit log + RBAC.

ZONE B CLIENT AGENT
  - Small systemd unit, verifies manifest.sig locally, stages, applies,
    auto-rolls-back on failure, reports.

2. LATEST PLAN - THE WIRED SYSTEM
============================================
Reference docs: PLAN.txt section 3, MANUAL.txt, plan.md, PROGRESS.txt.

DESIGN (single-server WSUS-relay, wired)
  - The update server is the ONLY machine online.
  - Agents (Rocky/Alma/RHEL, Ubuntu/Debian, Windows) live on an isolated
    host-only subnet with NO default route; they can only reach the server.
  - All update traffic flows THROUGH the server, by IP, over mTLS.
  - Source policy engine sits in front of every outbound fetch:
    ALLOWLIST (default-deny) + BLACKLIST, global across all source types,
    unknown hosts blocked + flagged for admin review, full audit log.

SERVER (Rust, crates/server)
  - Internal CA issuing per-agent mTLS client certs (CN = agent_id).
  - mTLS API on :8443: /enroll /register /inventory /updates /report /artifact.
  - Dashboard + JSON API on :8080 (plain HTTP): devices, packages vs latest,
    approvals, rings/promote, catalog search, sources, policy, operators,
    provisioning (network sweep + SSH push of agent + CA), audit log.
  - Catalog sync (crates/server/src/catalog.rs): apt (Ubuntu noble) + dnf
    (Rocky 8) metadata -> catalog.json keyed family/name. IPv4 resolution
    pinned for upstream hosts.
  - Windows updates WITHOUT WSUS: wucatalog source syncs the Microsoft
    Update Catalog for a KB allowlist; MSUs are served over mTLS from a
    local dropbox (<store>/windows/). KB-membership based availability.
  - Native mirrors per ring = the WSUS approval gate (approved-only repos).

AGENT (Rust, crates/agent)
  - Cross-platform static binary (musl; Windows gnu target).
  - Enroll once with token -> client cert; reuse cert on later runs.
  - Inventory: os-release, rpm/dpkg package list (Get-HotFix on Windows),
    kernel, bootloader, repos.
  - Poll loop (default 60s) -> pulls approved artifacts over mTLS /artifact
    -> installs OFFLINE in one transaction:
      RHEL:   dnf -y install --disablerepo=* ... --nogpgcheck <rpms>
      Debian: dpkg -i <debs>
      Windows: wusa.exe <msu> /quiet /norestart (DISM SSU->LCU fallback)
    -> reports outcome -> re-collects inventory.

WHAT THE WIRELESS VARIANT WOULD BE (scope inferred, NOT agreed/started)
  - Same trust model over Wi-Fi: server = online relay, agents talk to it
    only via mTLS; no direct internet for wireless nodes.
  - Likely additions if pursued:
      * agents/servers connected over Wi-Fi (access point / mesh) instead
        of wired host-only networking,
      * provisioning + artifact delivery over the wireless link,
      * possibly Wi-Fi specific concerns: radio isolation, EAP/PSK
        segmentation so wireless nodes stay on the isolated subnet,
        and throttling large MSU/MIRROR downloads over the air.
  - NONE of this has been designed or built.

So: the wireless system has had zero work done so far. It is a discussed
idea only; the air-gap (two-zone) and wired (single relay) systems are
fully planned, and the wired system is implemented and verified.
